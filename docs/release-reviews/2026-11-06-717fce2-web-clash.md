## 本次发现与处理

1. **Clash 请求来源校验绕过**：PowerShell 的路由匹配忽略大小写，原 `.StartsWith()` 区分大小写；混合大小写路径可绕过同源校验。另发现原始请求目标的 NUL 字符会被路由比较忽略。现统一大小写判定，在分发前拒绝控制字符；隔离测试覆盖混合大小写、非法 Host/Origin、预检、NUL 和正常同源请求。当前运行的 Web 服务已重启并做只读验证。
2. **监控页面 HTML 注入**：传感器名称及磁盘卷标被直接拼接进 HTML。隔离浏览器在修复前观察到两处脚本执行；现对名称、卷标和盘符进行文本/属性转义，修复后相同浏览器测试通过。
3. **CI 冒烟脚本虚假通过**：原 `scripts/smoke_test.bat` 为无 BOM 的 UTF-16LE，`cmd` 对不存在的程序返回空输出和退出码 0。现改为 ASCII，并用假 GUI 子系统程序检查缺失文件、两种异常退出及普通退出；移除会弹出交互窗口的 `-help`，CI 步骤设置超时。该测试只证明其指定检查行为，不证明真实清理成功。
4. **既有跨源清理信任边界**：默认 CORS 全开且 API Key 为空。独立审核在隔离服务和模拟任务中确认，来源不在 CORS 白名单时，简单 POST 仍可能触发已启用的任务桥。为保留现有跨项目接入契约，本次未改变该行为；`docs/WEB_BUTTON_INTEGRATION.md` 已澄清 CORS 白名单不能代替身份验证，以及内置页面目前没有 API Key 输入功能。
